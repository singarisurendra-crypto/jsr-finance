# PR-003: Customer Master & Loan Rescheduling Lifecycle

## Scope of Changes
1. **Loan Default Standards**:
   - Updated system default loan package to ₹10,000 / 52 weeks / ₹250 week (₹13,000 total repayable, 30% flat margin) across `DEFAULT_SETTINGS`, `DEFAULT_SCHEMES`, and customer modal defaults.
   - Fixed `setInstalmentsPreset` so hand-typed instalment amounts are preserved by updating margin instead of resetting amount.
2. **Historical Revision Floor Invariant**:
   - Enforced rule that a loan's total instalments cannot be reduced below the highest instalment number already received/recorded (`totalInstalments >= highestPaidNumber`).
   - Prevents accidental truncation and data loss of collected instalments during loan term edits.
3. **Dynamic Schedule Adjustment**:
   - When total instalments are increased, cleanly append new pending instalments.
   - When total instalments are decreased (down to the floor), prune only untouched trailing instalments.
4. **Synchronized Customer Profiles across Multi-Loans**:
   - Editing customer metadata (name, phone number, address, area) automatically propagates and updates across all active and completed loans for that customer number.
5. **Robust Input Validation**:
   - Removed silent substitutions (e.g. silently replacing 0 with 10000 or 200). Form enforces explicit validation errors for missing or invalid principal or instalment counts.
6. **Cloud-Synced Backup Restoration**:
   - Updated `exportDataBackup` to include the immutable transaction ledger.
   - Updated `importDataBackup` to actively push restored customer and transaction data to Cloud Firestore, preventing cloud listeners from immediately overwriting local restore with stale data.
