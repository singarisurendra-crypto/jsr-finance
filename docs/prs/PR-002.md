# PR-002: Security, Role-Based Access & Firestore Hardening

## Scope of Changes
1. **Firestore Security Rules (`firestore.rules`)**:
   - Replaced open `allow read, write: if true;` with collection-specific schema validation.
   - Made `transactions` collection append-only (`allow create: if ...; allow update, delete: if false;`), ensuring historical collection receipts can never be modified or deleted.
   - Protected `config/settings` from deletion.
2. **Elimination of Universal Backdoors & Leaks**:
   - Removed the universal bypass allowing any 4+ character username with PIN `1234`.
   - Removed the "1-Tap Quick Demo Sign-in" bypass button from the login screen (`index.html`).
   - Removed the default PIN hint popup from the login screen.
   - Replaced leaky login error messages with a generic, secure credential prompt.
3. **Multi-Tier Operational Roles**:
   - Established `Admin` (Owner) and `Collector` (Field Operator) roles.
   - Protected `deleteCustomer` so Field Collectors cannot delete customer loans.
   - Protected `clearAllData` ("Reset Demo Data") with role validation and typed `RESET` confirmation.

## Files Modified
- `firestore.rules`
- `index.html`
- `app.js`
